## 1. “创新点”先说明相对谁

| 参照 | 可描述的项目差异 | 技术价值 | 不应夸大的部分 |
|---|---|---|---|
| 经典无预测五级 | A 引入全局风格分量、Bimodal 与选择器；两版均有 BTB | 学习用历史换取更少控制流错误的设计方法 | 这些是成熟预测思想，不能据此认定原创 |
| 经典五级 | B 在 EX 后增加 BUFFER，并把读返回寄存化 | 处理存储路径时序与指令控制对齐 | 不能只说“加一级所以频率提升” |
| 模板支线 | A/B 活动核聚焦常用整数，预测与访存组织不同；模板含部分浮点路径 | 展示裁剪功能、配置资源与改造微结构 | 模板本地快照是否等于赛方初版、谁设计了什么未考证 |
| A 与 B | 强化预测结构 vs 简化预测结构；三源 vs 四源前递 | 比较预测成本、时序压力、load 返回与资源 | 多变量对比，不能作为单项优化的控制变量实验 |
| 单独 CPU 核 | SoC 集成虚拟 IO、BRAM、MMIO 和计数器 | 程序与硬件系统连接起来 | 不代表完成工业级总线、异常或可靠性验证 |
| 整理前工程 | 有效源码归一、原版快照隔离、引用与哈希检查 | 让后续研究可追溯、避免读错版本 | 工程管理改善不等同于微架构原创成果 |

证据参见[02](D:/codex_prj/fpga_dick/jyd-riscv-soc/docs/research/02-repository-soc.md)、[03](D:/codex_prj/fpga_dick/jyd-riscv-soc/docs/research/03-datapath.md)、[05](D:/codex_prj/fpga_dick/jyd-riscv-soc/docs/research/05-prediction.md)、[06](D:/codex_prj/fpga_dick/jyd-riscv-soc/docs/research/06-timing.md)。本版不写个人归属。

可以将工程价值概括为：“围绕 FPGA 上的流水 CPU，在预测复杂度、访存延迟、前递控制和时序之间作具体取舍，并能指出证据和设计限制。” 这比堆砌“高性能、创新预测、时序优化”更适合深入追问。

## 2. 先正确，再测量，再优化

下表的“确认”指静态事实，不代表本次观察到上板故障。编号对应[未来实验 V01—V12](D:/codex_prj/fpga_dick/jyd-riscv-soc/docs/research/11-validation.md)。

| P1 复位与跨域 | 同源 PLL 不同频率间有直接控制／数据连接，S | 需核实关系、脉冲捕获和总线一致性；按协议选择同步或握手 | V10；不能一概插两级同步器处理多位总线 |
| P1 性能 | load-use 重取与 rd=0 过滤不足，S/I | 潜在额外气泡；用有效源位、rd 非零，再评估保持式 interlock | V02—V04，正确性先通过，再统计多余重取 |
| P1 存储 | SB/SH 用读改写，S | 返回字、低位地址、写数据需一致 | V06/V07，未写字节必须保持 |
| P1 时序证据 | 历史 no_clock／未约束端点／I/O delay 缺项，H：[E17](D:/codex_prj/fpga_dick/jyd-riscv-soc/docs/research/09-evidence.md) | WNS 不能覆盖所有路径；调查历史网表或重建约束 | V11，检查每项原因与约束依据 |
| P2 性能优化 | A 的 PC→IROM 布线主导，B 返回链余量小，H | 从关键路径着手，评估映射、扇出、寄存边界 | V11/V12，比较同条件路径与执行时间 |

另需把接口契约写清：JALR 对齐、非法指令、非对齐 load/store、异常行为、复位释放和未初始化 GPR 不在本版合规保证内。规范预期与当前实现必须区分，不把“有 opcode”当成“所有语义都完成”。

## 3. 三条值得继续研究的方向

### 方向 A：可靠的流水控制

先补双源 load-use 等覆盖问题和无效源过滤，再把每级“有效、保持、冲刷”的语义统一。将重取式处理与保持式 interlock 对照：后者可能少重取，但需要更细的控制、预测元数据保持和存储副作用处理。

交付应是能检查寄存器提交与内存副作用的验证环境，以及所有依赖距离的结果，不是只增加几个 if 条件。

### 方向 B：可解释的预测训练

保存每条分支预测时的方向、目标、索引和有效性，明确预测失败后历史如何恢复、训练哪个表项。先证明简单 Bimodal 正确，再比较 A 风格组合预测的收益。

把 A 预测器移到 B 是候选课题；它可能增加前端组合路径。若需要独立预测级，流水和冲刷代价都会改变，不能默认 B 已有可复用的额外 IF2。

### 方向 C：同条件下的面积—时间比较

先固定 RAM 容量、指令程序、编译选项、工具与约束，建立执行时间而非仅频率的比较。结合周期统计和 routed 路径逐项解释变化；有需要再增加乘除法或浮点，而不是以功能数量代替基础可靠性。

## 4. 改进建议怎样变成复试答案

先说现象：“A 的双源 load 依赖 case 未覆盖。” 再说原因：“检测将两个命中位组合，却只处理 10/01。” 然后说改法与代价：“完整识别有效 RAW，处理 rd=0，并保持重取语义一致。” 最后说明验证：“用内存新值与寄存器旧值不同的指令序列，检查消费者采样值与最终写回。”

这样可以清楚表达分析能力，同时保持事实边界：本次只是找出代码事实并设计验证，没有修复 CPU，也没有虚构已完成实验。
