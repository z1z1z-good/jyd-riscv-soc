## 3. 纠错表：旧说法、证据与新口径

| 旧说法或容易沿用的表述 | 为什么不成立／不充分 | 当前应采用的表述 |
|---|---|---|
| 200M 版 CPU 跑 200 MHz | 输入时钟与 CPU PLL 输出混淆 | A CPU 配置 150 MHz，历史 clock summary 一致 |
| B 是 IF1/IF2/ID/EX/BUFFER/MEM/WB 七级 | 把异步 IROM 当成额外同步输出寄存级 | B 六级；if_id 是第一道取指寄存边界 |
| B 增加取指级，因此分支必罚三拍 | 额外取指级不存在 | EX 前仍两个年轻位置，精确罚拍需指定场景 |
| CPT 是第三套 BTB | CPT 只是选择器 | A 两套 BTB，CPT 无独立目标表 |
| A 用满 10-bit 全局历史索引 | XOR 结果进入 6-bit 索引线 | 当前索引只用低 6 位；历史更新时机另需核验 |
| AREA 是带局部历史表的预测器 | 实际只按 PC 索引二位状态 | 称 Bimodal 分量更准确 |
| _hypass 端口补偿 B 的 load | 顶层未连接这些端口 | BUFFER 旁路走顶层其他有效连线，load 还需等待 |
| A 紧邻 load-use 固定停一拍 | 当前清空前端并重取后继 | 简单例静态推演多两拍；见第 04 章条件 |
| 预测命中率 96%/88% 等是项目成果 | 未找到可追溯计数输入、日志或结果 | 不使用这些百分比 |
| 250 MHz 全由一次 retiming 获得 | A/B 同时改变多个变量，日志改善不能证明唯一因果 | 可确认结构改动与历史路径；因果收益需受控对照 |
| B 的面积与功耗都更低 | FF/LUT、BRAM、功耗并非同向；口径也不同 | 单列整个 top 的资源和工具估计，并说明 RAM 扩容 |
| 正 WNS 说明整机时序完全通过 | 原报告仍列约束覆盖缺项 | 仅已约束分析路径汇总为正，覆盖问题待查 |
| 0.450/0.540 W 是板上测量 | 原报告没有电源实测，未导入仿真活动文件 | 历史工具片上功耗估计 |
| 工程能打开代表功能已验证 | 文件引用和编译序检查不执行指令 | 与仿真自检、综合、实现、上板结果严格分开 |

## 4. 本次仍未解决的资料缺口

- 最初开发过程的全部对话、设计决策理由及赛方原始发布物来源未完整恢复。
- 历史 routed report 与某一精确 RTL／IP 快照的逐文件对应关系未建立；当前提交包含后来的整理，不能声称完全相同。
- 没有可核验的 CoreMark 原固件与分数、预测命中率、提交计数、完整指令合规结果或板上波形。
- 历史 no_clock 与未约束项的网表根因不能从当前文档反推。
- 作者真实意图与当前行为可能不同：代码注释如“应该打拍”“不知道为啥”是线索，不是正确性证明。
